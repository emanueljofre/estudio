08 — Unidad de Control ★ ciclo de instrucción
⚙️ M8.1 · Función de la UC
¿Cuál es la función de la Unidad de Control?
✅ Respuesta de examen La Unidad de Control (UC/UDC) es la encargada de la coordinación y administración de todas las tareas para ejecutar las instrucciones. Genera todas las señales eléctricas de control: internas (activan la ALU, FPU, registros) y externas (lectura, escritura). En síntesis: dirige el CPU en cada etapa del ciclo de instrucción.
🧠 contextoEl profe la llama "el gerente" (la ALU es "su calculadora"): no calcula, ordena. Es uno de los 4 componentes del CPU (UC + registros + ALU + interconexión interna).
Siglas: UC/UDC = Unidad de Control · ALU = Arithmetic Logic Unit · FPU = Floating Point Unit · CPU/UCP = Unidad Central de Proceso.
📚 M8.2 · Niveles de instrucción
¿Qué son las instrucciones de alto nivel, las de bajo nivel y las microinstrucciones?
✅ Respuesta de examenTres niveles distintos, y cada uno se almacena en un lugar diferente:
  • Alto nivel: lenguajes como C++, Java, Python (el hardware no las entiende directo; el compilador las traduce). Existen como archivo fuente en disco.
  • Bajo nivel / código máquina: la instrucción en binario/hexadecimal que ejecuta el CPU; se escribe en assembler con mnemónicos (ej. ADD AX, 5) que el ensamblador convierte 1:1 al binario real. Residen en la memoria principal (RAM) y se traen de a una al Registro de Instrucción (IR). Son la cara visible de la ISA (lo que ve el programador).
  • Microinstrucción: cada micro-tarea elemental en que la UC descompone una instrucción; forman un microprograma almacenado en la memoria de control (ROM) dentro de la UC (lo pone el fabricante). Una se ejecuta en ~1 ciclo de reloj. No son parte de la ISA: son la implementación interna de la UC (microarquitectura), invisibles al programador y propias de cada CPU — por eso dos CPUs con la misma ISA pueden tener microcódigo distinto, y una UC cableada (ARM/RISC) directamente no las tiene.
🧠 contextoAnalogía restaurant: cliente pide papas (alto nivel) → mozo lleva el pedido a la cocina (bajo nivel, al IR) → chef = UC dicta tareas → cocineros = circuitos ejecutan cada microinstrucción.
Siglas: IR = Instruction Register (Registro de Instrucción) · ISA = Instruction Set Architecture.
🧩 M8.3 · Formato de instrucción
¿Cómo es el formato de una instrucción? ¿Cuál es la parte que se decodifica?
✅ Respuesta de examenToda instrucción de máquina tiene el formato [COP][Operando(s)] — también escrito [Código de Operación][Objeto]. Está formada por dos partes:
  • COP — Código de Operación (OpCode): indica QUÉ operación realizar (mover, sumar, saltar…). Es un número que identifica de forma única a esa operación dentro del set de instrucciones.
  • Operando(s) / Objeto(s): indican SOBRE QUÉ se opera. Pueden ser un dato inmediato, un registro o una dirección de memoria. Una instrucción puede tener cero, uno o varios operandos.
La parte que se decodifica es el COP. El decodificador de la Unidad de Control lo interpreta y genera las señales de control que activan los circuitos para ejecutar la operación. Los operandos no se decodifican: se toman tal cual como dato o como dirección. Según el tamaño, el formato puede ser de longitud fija (MIPS), variable (VAX) o combinada (Intel x86).
Ejemplo desarmado · MOV AX, 1A3F — en palabras: «cargá el valor 1A3F en el registro AX». Cada parte:
MOVel mnemónico de la operación (de move): instrucción de transferencia, copia un dato a un destino.
AXregistro acumulador de 16 bits del microprocesador (8086) → acá es el destino donde se guarda el dato. («A» de Accumulator, «X» de registro extendido de 16 bits.)
1A3Fel dato inmediato en hexadecimal → es el operando que se carga en AX.
MOV AX,1A3F →
COPOBJOBJB8163F161A16
= B83F1A16
Traducida a código máquina ocupa 3 bytes. Arriba están los campos del formato, abajo los bytes reales: el COP es B816 y ya codifica «MOV a AX» (operación + registro destino) — por eso es lo único que se decodifica; los otros dos bytes (3F16 1A16) son el operando 1A3F guardado en little-endian (el byte bajo 3F16 va primero, después el alto 1A16).
🧠 contexto⚠️ Trampa del profe: la computadora no "busca el COP", busca una instrucción completa que adentro tiene el COP — el COP no anda suelto en memoria.
Siglas: COP = Código de Operación (OpCode) · MOV = move, transferencia · AX = registro Acumulador de 16 bits · inmediato = el dato viaja dentro de la propia instrucción.
🗂️ M8.5 · Set de instrucciones / ISA
¿Qué es el set de instrucciones o ISA? ¿Dónde se encuentra?
✅ Respuesta de examenEl set de instrucciones es el repertorio completo de operaciones que el microprocesador puede decodificar y ejecutar en su circuito físico — el catálogo de instrucciones que el hardware "entiende". La ISA (Instruction Set Architecture) es el concepto formal y más amplio: además del set de instrucciones, define los registros, los tipos de datos, los modos de direccionamiento y el modelo de memoria. Es la interfaz (contrato) entre el hardware y el software de bajo nivel —código máquina y assembler—: a partir de estas instrucciones el programador o el compilador construyen los programas (la instrucción es el ladrillo; el programa se arma combinándolas). ¿Dónde está? La ISA en sí es una especificación (el contrato visible al programador); lo que está físicamente en la memoria de control (ROM de control) —dentro de la UC, dentro del microprocesador— es el microprograma que la implementa (en una UC microprogramada; una UC cableada corre la misma ISA sin ROM → M8.4). ⚠️ El profe lo resume como «la ISA se encuentra en la ROM de control».
🧠 contextoDos arquitecturas con ISA distinta (x86 vs ARM) son incompatibles: "como francés y alemán" — pero un mismo binario corre en cualquier implementación física de la misma ISA (un i3 y un i9 comparten el set x86 aunque internamente sean distintos). Dos filosofías de diseño: CISC (muchas instrucciones complejas, ej. x86) vs RISC (pocas instrucciones simples y uniformes, ej. ARM, RISC-V). Grupos del 8086: transferencia, aritméticas, lógicas, cadenas, saltos, control.
Siglas: ISA = Instruction Set Architecture · ROM = Read-Only Memory · CISC = Complex Instruction Set Computer · RISC = Reduced Instruction Set Computer.
08 · dicotomías clave ★
⚔️ M8.4 · UC cableada vs microprogramada
¿Qué es una UC cableada y una microprogramada? ¿Qué diferencia ocurre al decodificar el COP?
✅ Respuesta de examenSon las dos formas de implementar la Unidad de Control. La cableada usa circuitos lógicos fijos: al decodificar el COP activa el hardware directamente (más rápida, poco flexible; típica de RISC/ARM). La microprogramada guarda un microprograma en la memoria de control (ROM): el COP decodificado funciona como dirección de entrada a ese microprograma, que recién ahí emite las señales (versátil/actualizable, más lenta; x86 son híbridas). La diferencia al decodificar el COP: cableada = COP→hardware directo; microprogramada = COP→dirección→microprograma→señales.

08 · ciclo de instrucción ★ el profe exige castellano completo
🔄 M8.7 · Etapas del ciclo de instrucción
¿Qué etapas tiene el ciclo de instrucción?
✅ Respuesta de examenEl ciclo de instrucción tiene cuatro etapas (en castellano completo, como exige la rúbrica):
  • 1 · Búsqueda de la instrucción (Fetch): se trae la instrucción desde la Memoria Principal —la posición que apunta el PC— al Registro de Instrucción (IR).
  • 2 · Decodificación (Decode): el decodificador de la UC interpreta el COP y emite las señales de control.
  • 3 · Búsqueda de operandos (Operand Fetch) — solo si hace falta: si la instrucción necesita operandos que no lleva adentro, se traen de memoria o registros.
  • 4 · Ejecución (Execute): se realiza la operación (la UC ordena a la ALU si es aritmético-lógica) y se escribe el resultado en el destino.
En el procesador básico la escritura del resultado va dentro de la ejecución; en procesadores con pipeline (como el Pentium) es una etapa separada (Escritura / Writeback).
📊 RÚBRICA: "No me pongan FI, DI, FO, EX. Escríbanme qué es cada cosa en castellano y completo." Y ⚠️ no confundir con el ciclo de interrupción (Solicitud→Reconocimiento→Atención→Retorno).
🔎 M8.8 · Búsqueda y decodificación
¿Qué ocurre durante la búsqueda y la decodificación?
✅ Respuesta Búsqueda (IF): la UC pone en el bus de direcciones la posición que apunta el PC, da señal de lectura (bus de control); la instrucción viene por el bus de datos al IR, y se actualiza el PC.
Decodificación (ID): un decodificador interpreta el COP del IR y emite las señales de control (acá se bifurca cableada/microprogramada).
Siglas: MP = Memoria Principal · IF/ID = Instruction Fetch / Decode.
❓ M8.9 · ¿Siempre operandos?
¿Siempre se deben buscar operandos?
✅ RespuestaNo. La OF es ir a leer el operando a la memoria (MP); solo se hace cuando el operando está en memoria. Si ya está disponible, se omite (decodificación → ejecución directo). Según el modo de direccionamiento (que define dónde está el operando):
  • NO necesita OF (ya disponible) → implícito (en el COP, INC AX), inmediato (literal en la instrucción, ADD AX, 4) y cuando el operando ya está en un registro (ADD AX, BX → acceso interno, no toca la MP).
  • SÍ necesita OF (está en memoria) → directo ([120]), indirecto de registro ([BX]: el registro tiene la dirección, el dato está en MP) e indirecto (puntero→puntero, varios accesos).
⚠️ Lo que dispara la OF es que el dato esté en memoria: BX (operando en el registro) → NO; [BX] (lo que BX apunta, en MP) → SÍ.
🧠En el diagrama: camino "verde" (con OF) vs camino "rojo" (sin OF, ID→EX).
▶️ M8.10 · Ejecución
¿Qué ocurre durante la ejecución?
✅ RespuestaSe realiza la ejecución propiamente dicha de la instrucción y el procesamiento de los datos. La UC emite las señales de control que activan el circuito que corresponda según el tipo de instrucción:
  • Aritmética/lógica (suma, resta, desplazamientos de bits, lógicas): la UC ordena a la ALU (dirige, no calcula); los operandos (si los hay) entran a la ALU, que devuelve el resultado y actualiza los flags del registro de estado.
  • No aritmética/lógica: se ejecuta sin ALU — ej. un MOV mueve datos entre registros/memoria, un salto carga/modifica el PC, una de control (CLC, STI) toca flags/estado.
En el procesador básico la escritura del resultado va en esta etapa (en el Pentium es una etapa aparte), y cómo se generan las señales depende de si la UC es cableada o microprogramada. Al terminar arranca un nuevo ciclo (o el de interrupción si hay solicitud).
💾 M8.11 · Escritura
¿Qué es la escritura luego de la ejecución?
✅ RespuestaEs la etapa de Escritura (Writeback): se guarda el resultado de la operación en su destino — normalmente un registro, o una posición de memoria (en un store). No es lo único que cambia: una operación aritmético/lógica también actualiza los flags del registro de estado (CF, ZF, SF, OF…), aunque eso lo hace la ALU durante la ejecución. En el procesador básico la escritura va dentro de la ejecución; con pipeline (Pentium) es una etapa separada: Prefetch → Decode1 → Decode2 → Execute → Writeback.
⏱️ M8.12 · ¿Cuándo sensa interrupciones?
¿Cuándo el CPU sensa si hay alguna solicitud de interrupción?
✅ RespuestaAl final de cada ciclo de instrucción (último pulso de reloj), la UC chequea si hay una solicitud enmascarable pendiente (si el flag IF lo permite). Las no enmascarables (NMI) no esperan: suspenden el ciclo en cualquier punto.
🧠El DMA también puede frenar el ciclo en ciertos puntos → "robo de ciclo" (es robo de bus, NO una interrupción: el CPU pierde 1 ciclo pero no salta a ninguna rutina). La interrupción real del DMA llega al terminar la transferencia.
Siglas: IF = Interrupt Flag · NMI = Non-Maskable Interrupt · DMA = Direct Memory Access.
📏 M8.13 · Longitud de palabra del procesador
¿Qué es la longitud de palabra de un CPU (procesador)?
✅ Respuesta de examenLa palabra (word) del procesador es la unidad normal de datos que el CPU almacena, procesa y transmite — el ancho del camino de datos entero: registros de propósito general + ALU. Su longitud es siempre múltiplo de 2 y normalmente múltiplo de 8 bits (un número entero de bytes). Sus múltiplos con nombre propio son Double Word (DW) y Quad Word (QW).
8086/8088: palabra = 1 byte · DW = 16 bits · QW = 32 bits
Procesador moderno: palabra = 64 bits = 8 bytes
Primeros procesadores: 4 y 8 bits
🧠⚠️ No confundir con la palabra de memoria: la del procesador es cuánto opera/transmite el CPU de una vez; la de memoria es lo que entra en cada dirección de la RAM. El procesador pide UNA palabra; la RAM/caché le trae un BLOQUE entero (localidad). Se rige por los registros enteros (GP) y la ALU; la FPU/SIMD (80–512 bits) y los buses (datos/direcciones) pueden tener otro ancho. En x86 moderno QWORD = 64 bits. El profe la resume como los bits que entran al registro de instrucción (registro de propósito específico, no GP).
Siglas: DW = Double Word (palabra doble) · QW = Quad Word (palabra cuádruple) · word = palabra.
🧱 M8.13b · Longitud de palabra de memoria
¿Qué es la longitud (tamaño) de palabra de memoria?
✅ Respuesta de examenEs la cantidad de bits almacenados en cada posición direccionable de la memoria principal (RAM) — una "fila" de la matriz de celdas, lo que se lee o escribe en un acceso a una dirección. En las DRAM suele ser de 8 bits = 1 byte: cada palabra de 8 bits está formada por 8 celdas (en DRAM, 1 MOSFET + 1 capacitor por celda = 1 bit; en SRAM, flip-flops). Se accede con una dirección binaria que un decodificador traduce a la palabra buscada.
🧠La memoria se organiza en una matriz de filas × columnas; cada fila = una palabra de n bits accesibles en paralelo. ⚠️ No confundir con el ancho de la dirección: esos bits definen cuántas posiciones hay (2ⁿ), no el tamaño de cada palabra. ⚠️ Distinta de la palabra del procesador: un CPU de 64 bits pide su palabra de 8 bytes, pero la RAM la sirve leyendo varias palabras de memoria y trae un bloque completo a la caché (localidad espacial). "La memoria se divide en bloques, la caché en líneas, y las palabras son lo que pide el procesador."
Siglas: DRAM/SRAM = Dynamic/Static RAM · celda = unidad física que guarda 1 bit · MOSFET = transistor de la celda DRAM.

🆕 M8.16 · Intel 80386
¿Qué características principales introdujo el procesador 80386?
✅ RespuestaEl 80386 (1985) introdujo: arquitectura de 32 bits (registros, ALU, direccionamiento); MMU con direccionamiento virtual de 4 GB; memoria virtual paginada; modo protegido. Su set de 32 bits lo mantienen todos los x86. UC microprogramada.

08 · complementos del repaso ★ los preguntó en clase
🔧 M8.17 · Compilado vs interpretado
¿Qué diferencia hay entre un lenguaje compilado y uno interpretado?
✅ Respuesta de examenSon dos formas de llevar un programa de alto nivel a código que el CPU pueda ejecutar:
  • Compilado: un compilador traduce todo el código fuente a código máquina de una sola vez, y genera un ejecutable. Se traduce una vez y corre muchas → más rápido en ejecución. Ej.: C, C++.
  • Interpretado: un intérprete lee y ejecuta el programa línea por línea en tiempo de ejecución, sin generar un ejecutable aparte → más portable pero más lento. Ej.: Python.
🧠 contextoNexo con M8.2: el hardware solo entiende código máquina; lo que cambia es cuándo se traduce. Hay híbridos (Java/C#): compilan a bytecode que corre sobre una máquina virtual → M8.18.
🖥️ M8.18 · Compatibilidad de arquitectura y virtualización
¿Un programa compilado para una arquitectura corre en otra? ¿Cómo se logra que sí?
✅ Respuesta de examenNo directamente. El ejecutable está en el código máquina de una ISA concreta (ej. x86); otra ISA (ej. ARM) tiene instrucciones distintas → son incompatibles ("como francés y alemán"). Para correrlo igual se usa virtualización: una capa de software (máquina virtual / emulador) que traduce o interpreta las instrucciones de la arquitectura origen sobre la de destino. Ejemplo clásico: la JVM ejecuta el mismo bytecode Java en cualquier plataforma que tenga una JVM.
🧠 contextoConecta con M8.5 (ISA): la portabilidad la da la VM, no el binario. (Rosetta 2 de Apple traduce x86→ARM con el mismo principio.)
Siglas: VM = Virtual Machine · JVM = Java Virtual Machine · ISA = Instruction Set Architecture.
⏲️ M8.19 · Hertz y operaciones por segundo
¿Qué es un Hertz? Si un CPU corre a 4 GHz y una suma tarda 4 ciclos, ¿cuántas sumas por segundo hace?
✅ Respuesta de examenUn Hertz (Hz) es un ciclo (una oscilación) por segundo; mide la frecuencia del reloj. 1 GHz = 10⁹ ciclos/segundo. Cálculo por regla de tres: a 4 GHz el CPU hace 4×10⁹ ciclos/s; si cada suma consume 4 ciclos → 4×10⁹ ÷ 4 = 10⁹ = 1.000.000.000 de sumas por segundo.
operaciones/s = frecuencia (ciclos/s) ÷ ciclos por operación (CPI)
🧠 contextoEl profe lo planteó como repaso ("vamos séptimo grado"). Es la base del IPC (M9.2): acá 1 suma = 4 ciclos → IPC 0,25; con el pipeline lleno = 1 ciclo → IPC 1. La frecuencia la genera el oscilador de cristal de la placa (M10.2).
Siglas: Hz = Hertz · GHz = GigaHertz (10⁹ Hz) · CPI = ciclos por instrucción (inverso del IPC).

🏭 M9.1 · Pipeline: qué es y ventajas

📐 M9.3 · Superpipelining
¿Qué es el superpipelining?
✅ RespuestaDividir el pipeline en un número mayor de etapas más pequeñas, para trabajar con más instrucciones a la vez y poder elevar la frecuencia del CPU.

🟢 M9.7 · ¿Por qué el Pentium era superescalar?
¿Por qué el Intel Pentium era un procesador superescalar?
✅ Respuesta (rúbrica textual)El Pentium (1993) tenía 2 pipelines de enteros (U y V) con 2 ALUs → ejecutaba 2 instrucciones de 32 bits a la vez (por eso su bus de datos era de 64 bits); y tenía arquitectura Harvard (caché de código y de datos separados). Fue el primer superescalar de Intel.
🧠"No te voy a preguntar los 3,1 millones de transistores, pero sí que era superescalar, 2 ALUs, bus de 64 bits, Harvard." (No hacía ejecución fuera de orden: era "obediente".)
🧱 M9.8 · Los 3 problemas del pipeline ⚡ ENTRA — rúbrica dictada
¿Cuáles son los tipos de problemas que ocurren al implementar un pipeline?
✅ Respuesta de examenHay tres tipos de problemas, cada uno con su solución: de datos (una instrucción depende del resultado de otra anterior), de control (saltos condicionales) y de estructura (varias instrucciones piden el mismo recurso ocupado).
1 · DATOS
Una instrucción necesita el resultado de otra anterior que no terminó (ej. R4 = R2+R3 con R2 de la previa) → burbujas.
Solución: forwarding (pasa el resultado de la ALU directo a la instrucción que lo espera, sin aguardar el Writeback), registros de renombramiento (registros físicos extra que evitan falsas dependencias por reusar un mismo nombre) y/o ejecución fuera de orden (corre otras instrucciones independientes mientras el dato no llega).
2 · CONTROL
Un salto condicional: no se sabe qué instrucción cargar hasta evaluar la condición → si se vacía el pipeline, ciclos perdidos.
Solución: predictores de saltos — adivinan si el salto se toma y su destino para seguir llenando el pipeline sin esperar a evaluar la condición (estáticos = regla fija; dinámicos = por historial, >95%, con BTB que guarda el destino); si fallan, se descarta lo especulado.
3 · ESTRUCTURA
Varias instrucciones quieren la misma unidad ocupada (ej. raíz cuadrada en la FPU) → esperan.
Solución: más unidades funcionales — duplicar el hardware (varias ALUs/FPUs) para que dos instrucciones que piden el mismo recurso se ejecuten a la vez en lugar de esperar.
📊 RÚBRICA: enumerar los 3 tipos, dar un ejemplo y la solución de cada uno. Omitir uno = perder puntaje.
Siglas: BTB = Branch Target Buffer · FPU = Unidad de Punto Flotante.

👥 M9.11 · Multiprocesamiento simétrico
¿Qué es el multiprocesamiento simétrico (SMP)?
✅ Respuesta de examenEs una arquitectura con dos o más procesadores de características similares que comparten el mismo espacio de memoria principal y de E/S, con tiempos de acceso similares, donde todos ejecutan las mismas funciones y están gobernados por un único sistema operativo integrado. Es transparente al usuario (ve una sola máquina). Sus 5 características:
1 · 2 o más procesadores similares
2 · comparten memoria y E/S
3 · tiempos de acceso similares a MP
4 · todos ejecutan las mismas funciones
5 · un único Sistema Operativo
🧠Transparente al usuario. El bus compartido es el cuello de botella → se mitiga con cachés L1/L2/L3. Los SMP son UMA.
⚖️ M9.11b · Simétrico (SMP) vs Asimétrico (AMP)
¿Qué diferencia hay entre multiprocesamiento simétrico y asimétrico?
✅ Respuesta de examen Simétrico (SMP): procesadores/núcleos pares (iguales); cualquier tarea puede ir a cualquier núcleo, gobernados por un único SO que los trata por igual, sin maestro. Ej.: multinúcleo homogéneo (Core i7).
Asimétrico (AMP): procesadores con roles o capacidades distintos — un núcleo maestro reparte trabajo a núcleos especializados, o núcleos de distinto tipo. Ej.: PS3 / Cell (1 PPE maestro + SPEs vectoriales especializados); núcleos de rendimiento vs eficiencia (P/E-cores, big.LITTLE).
Siglas: SMP = Symmetric Multiprocessing · AMP = Asymmetric Multiprocessing.
🖧 M9.12 · Clusters
¿Qué son los Clusters?
✅ Respuesta de examenConjunto de computadoras completas interconectadas por una red de área local (LAN: fibra o Ethernet de alta velocidad) que trabajan como una sola mega-computadora. Cada computadora es un nodo. A diferencia del SMP, cada nodo es una máquina entera con su propio procesador, su propia memoria y su propio sistema operativo (no hay un SO único que los gobierne a todos). Lo que sí comparten es el almacenamiento (típicamente RAID) por la red. El acceso a memoria es NUMA (heterogéneo: depende del nodo/región), frente al UMA uniforme del SMP.
🧠Acoplamiento débil (vs el fuerte del SMP, que comparte memoria por bus). RAID: arreglo de discos con uno redundante — si uno falla, se reconstruyen los datos. Escalan a millones de núcleos (supercomputadoras).
Siglas: LAN = Local Area Network · RAID = Redundant Array of Independent Disks.
🧠 M9.13 · UMA vs NUMA
¿Qué diferencia hay entre el acceso a memoria UMA y NUMA?
✅ RespuestaEn un sistema MIMD (multiprocesador) varios procesadores acceden a memoria; según si ese acceso tarda lo mismo para todos o varía, se distinguen dos arquitecturas de memoria:
UMA (uniforme): mismo tiempo de acceso a cualquier región para todos los procesadores (típico de SMP).
NUMA (no uniforme): el tiempo depende de la región de memoria / del nodo (típico de clusters).
🧠CC-NUMA = NUMA + coherencia de caché.
Siglas: UMA/NUMA = (Non-)Uniform Memory Access.

🗃️ M9.15b · Buffers del back end detalle de M9.15 · el profe: «muy importante» del ROB
¿Qué buffers tiene el back end?No es una pregunta aparte: es parte de la respuesta de M9.15. El profe los explicó dentro del pipeline (clase 2026-05-11) y dijo «muy importante» del ROB y la estación de reserva — pero no los toma sueltos.
✅ Los tres buffersEl back end ejecuta fuera de orden apoyándose en tres buffers:
  • ROB — Reorder Buffer (buffer de reordenamiento): las micro-ops entran en orden y guarda el orden original del programa; al retirar, reordena las escrituras finales a ese orden. Es el buffer clave del OoO.
  • Ventana de instrucciones / Estación de reserva (reservation station): aloja las micro-ops esperando despacho; los despachantes (schedulers) las envían fuera de orden por los puertos a las unidades de ejecución.
  • Buffer de almacenamiento (store buffer): registros temporales que sostienen resultados intermedios para el forwarding entre instrucciones.
🧠 no confundirEsos son los del Back End. Los buffers del Front End son otros: cola/buffer de instrucciones (esperando decodificación), caché de micro-ops y la BPU + BTB (predicción de saltos). El Allocator (asignación) es la frontera entre ambos. Conecta con M9.15.
Siglas: ROB = Reorder Buffer · BPU = Branch Prediction Unit · BTB = Branch Target Buffer · OoO = Out of Order.
🔁 M9.15c · ¿Por qué se reordenan las escrituras? ⚡ PREGUNTA DE EXAMEN REAL
¿Por qué los datos se vuelven a ordenar después de ser procesados por el Back End?
✅ Respuesta de examenPorque el Back End ejecuta las micro-ops fuera de orden (según el flujo de datos), pero el resultado debe escribirse en caché y luego en memoria en el orden original que el programador puso. El ROB (Reorder Buffer) anotó el orden de entrada y, al retirar (etapa 9), reordena las escrituras a ese orden. Si se escribiera en el orden caótico de ejecución, el estado de memoria quedaría inconsistente con lo que el programa especificó. En síntesis: se reordenan para poder escribirse en memoria respetando la semántica secuencial del programa.
🗣️ verbatim del profe (clase 2026-05-18)«El Back End recibe el buffer de reordenamiento, recibe las instrucciones en orden, anota cuál es el orden original, las desordena y las prepara para la ejecución fuera de orden… y cuando se ejecutan, después el ROB —o un buffer similar— escribe los datos en memoria, en realidad en caché y después en memoria, en el orden original que el programador había puesto.»
🧠 si piden profundizarEl destino (memoria) es el motivo central, pero reordenar también habilita: excepciones precisas (saber exactamente en qué instrucción frenar) y revertir la especulación (descartar resultados de un salto mal predicho antes de escribir). Conecta con M9.15 / M9.16.
Siglas: ROB = Reorder Buffer (buffer de reordenamiento) · OoO = Out of Order.
🔀 M9.16 · Ejecución fuera de orden
¿Cómo se implementa la ejecución fuera de orden (OoO) para acelerar el cómputo?
✅ RespuestaEl procesador analiza las dependencias del flujo de datos: si una instrucción depende de un resultado no listo, ejecuta otras independientes posteriores; cuando el dato está listo, ejecuta la dependiente. Las escrituras se reordenan al orden original (ROB). Usa forwarding + registros de renombramiento.
🧠"Le digo A,B,C,D y el procesador hace A,C,B,D" = procesadores "desobedientes". Resuelve el problema de datos.
Siglas: OoO = Out of Order.

12 — Interrupciones y Excepciones ★ ciclo de 4 etapas · tipos 0–4
🌳 M12.1 · Interrupciones vs excepciones
¿Qué diferencia hay entre las interrupciones y las excepciones?
✅ Respuesta de examen Interrupciones = HARDWARE, por un evento externo e impredecible (enmascarables / no enmascarables). Excepciones = SOFTWARE, internas: detectadas por el procesador (error al ejecutar, ej. división por 0) o programadas (instrucciones que generan una excepción a propósito — "pseudo-interrupciones": INTO, INT3, INT XX16). Diferencia central: la interrupción es de hardware/externa/impredecible; la excepción es de software/interna (y las programadas son predecibles).
Siglas: ISR = Interrupt Service Routine (Rutina de Servicio de la Interrupción).
🔁 M12.2 · Ciclo de interrupciones enmascarables (4 etapas) ⚡ + TRAMPA #1
¿Cuáles son las etapas de las interrupciones enmascarables?
✅ Respuesta de examenEl ciclo de interrupción tiene cuatro etapas: 1 · Solicitud (el dispositivo manda la señal INTR a un pin del CPU), 2 · Reconocimiento (el CPU termina la instrucción en curso, responde INTA, pone IF=0, lee el Tipo, accede a la IVT y hace PUSH del Contador de Programa CS:IP + las banderas), 3 · Atención (carga la dirección de la ISR y la ejecuta) y 4 · Retorno (la instrucción IRET hace POP y vuelve al programa interrumpido).
1 · Solicitud (Request) — el dispositivo envía la señal INTR a un pin del CPU. ("le toca timbre")
2 · Reconocimiento (Acknowledge) — el CPU termina la instrucción en curso, responde INTA, pone IF=0, lee el Tipo (1 byte), accede a la IVT, y hace PUSH del Contador de Programa (CS:IP) + las banderas. [la más complicada]
3 · Atención — carga la dirección de la ISR en el contador de programa y ejecuta la ISR.
4 · Retorno — la instrucción IRET hace POP (recupera CS, IP y flags) y vuelve al programa interrumpido.
⚠️ TRAMPA #1 (el profe la nombra explícitamente): "no se confundan con el ciclo de instrucción, me pasa en los exámenes." El ciclo de instrucción = búsqueda → decodificación → operandos → ejecución. El de interrupción = Solicitud → Reconocimiento → Atención → Retorno. No tienen nada que ver.
Siglas: INTR = Interrupt Request · INTA = Interrupt Acknowledge · IVT = Interrupt Vector Table · IRET = Interrupt Return.

⬆️ M12.8 · El retorno (POP / IRET)
¿En qué consiste el retorno? ¿Qué datos necesita recuperar el CPU?
✅ RespuestaEl retorno se hace con IRET (Interrupt Return), que ejecuta un POP y recupera: CS, IP (juntos = Contador de Programa) y los Flags. Restablece el contexto y el control vuelve al programa interrumpido "como si nada hubiese ocurrido".
🧠Es la operación inversa del Reconocimiento: lo que se hizo PUSH al entrar se hace POP al salir. IRET recupera solo CS:IP + flags (lo del hardware); los registros de datos los restaura la ISR con POP, antes del IRET (orden inverso al PUSH). El IRET va último, con la pila ya en el frame del hardware.

Al entrar a una ISR el CPU pone IF=0. Para anidar, la primera instrucción de la ISR debe ser STI (IF=1). Sin STI, la nueva interrupción se ignora hasta que termina la ISR actual.

🧮 M14.1 · Qué es DEBUG
¿Qué es el DEBUG y para qué se usa?
✅ Respuesta de examenDEBUG es un depurador y ensamblador en línea del MS-DOS (hoy se corre en emuladores como DOSBox) que permite escribir, ver y ejecutar instrucciones en lenguaje ensamblador del 8086 operando directamente sobre los registros y la memoria. Es la herramienta de la parte práctica de la materia. Direcciones y valores se manejan en hexadecimal.
📊 El profe: "el de assembler es importante porque se tiene que tomar sí o sí, es la parte práctica."
⌨️ M14.2 · Comandos del DEBUG ⚡ "esto les voy a preguntar"
¿Cuáles son los comandos del DEBUG y qué hace cada uno?
✅ Respuesta de examenDEBUG se maneja con comandos de una sola letra (seguidos de una dirección u operando en hexadecimal). Los que se toman:
ComandoAcciónEjemplo
Rver los registros (y editarlos: R + nombre)R · R IP
Dver la memoria como datos (volcado hex + ASCII)D 100
Uver la memoria como instrucciones (desensambla)U 100
Eeditar / escribir en una posición de memoriaE 300
Aempezar a ensamblar (escribir instrucciones)A 100
Pejecutar paso a paso (sin entrar en subrutinas)P
GGo: ejecutar hasta el finalG
📊 RÚBRICA (el profe los ensayó en clase): "¿con qué instrucción veo los registros? ¿con qué comando veo la memoria como datos? ¿cómo edito la posición 300 de memoria? Eso les voy a preguntar."
🧠 contextoDiferencia clave: D muestra la memoria como datos, U la misma memoria como instrucciones desensambladas. R IP permite modificar el contador de programa para reejecutar el código (M8.6).
🗄️ M14.3 · Registros de propósito general (H/L)
¿Cuáles son los registros de propósito general del 8086 y cómo se dividen?
✅ Respuesta de examenSon AX, BX, CX, DX — los que el programador usa libremente. Cada uno es de 16 bits y se parte en dos mitades de 8 bits: parte alta (H, high) y parte baja (L, low). Así AX = AH + AL. Nombres: A = acumulador, B = base, C = contador, D = datos.

MOV AX,1A3F → mueve 16 bits (4 dígitos hex)

AH + AL · 8 bits c/u

MOV AL,3F / MOV BL,07 → 8 bits (2 dígitos hex)
⚠️ El sufijo decide el tamaño. El profe: "cuando pongo BL no me va a tomar 4 números, me va a tomar 2."
🧾 M14.4 · Instrucciones que toma
¿Qué instrucciones de ensamblador hay que saber para el parcial?
✅ Respuesta de examenTres:
  • MOV dest, origen — copiar (transferencia): pone en dest el valor de origen.
  • ADD dest, origen — sumar: dest = dest + origen.
  • INC reg — incrementar en 1 el registro.
📊 El profe: "les voy a tomar MOV que es copiar, ADD que es sumar e INC que es incrementar, y listo, con esas me alcanza."
🧠 contextoADD e INC actualizan los flags del registro de estado (M14.7); MOV no.
🎯 M14.5 · Direccionamiento en ensamblador: los corchetes
En ensamblador, ¿cómo se distingue el direccionamiento inmediato del directo?
✅ Respuesta de examenPor los corchetes:
  • Inmediato (sin corchetes): el operando es el valor literal. ADD AX,4 suma el número 4.
  • Directo (con corchetes): el operando es una posición de memoria. MOV CX,[B310] copia a CX el contenido de la dirección B310, no el número B310.
  • Implícito: sin operando explícito (ej. INC AX).
📊 El profe: "esto es importante que lo sepan porque a veces lo pregunto… cuando había un corchete era un direccionamiento directo." El corchete cambia por completo el significado. Conecta con M8.15.
📝 M14.6 · Tipo de preguntas de ensamblador ⚡ con respuesta modelo
Ejemplos del estilo de consigna que el profe dijo que va a escribir, con su instrucción correcta.
✅ Resueltos
Escribí una instrucción que sume en el registro AX lo que está en la posición de memoria 1100.
ADD AX,[1100] — directo: los corchetes indican que se suma el contenido de la dirección 1100 (no el número 1100).
Usá direccionamiento inmediato para sumar 8 a la parte alta del registro BX.
ADD BH,8 — BH = parte alta de BX; sin corchetes = inmediato (el literal 8).
Cargá en la parte baja del registro CX el operando 3.
MOV CL,3 — CL = parte baja de CX; MOV = cargar/copiar.
📊 El profe: "eso va a ser las preguntas de assembler." Patrón: te dan la operación + el registro (entero o mitad H/L) + el modo de direccionamiento; vos escribís la instrucción.
🔄 M14.6b · El ejercicio inverso: dada la instrucción, identificá el modo ⚡ "también se los voy a tomar"
El otro sentido de la pregunta: el profe te escribe una instrucción y vos decís qué modo de direccionamiento usa.
✅ Resueltos
¿Qué modo de direccionamiento usa INC AX?
Implícito — no hay operando explícito; el "1" que se incrementa está sobreentendido en la propia instrucción.
¿Qué modo de direccionamiento usa MOV AX,12?
Inmediato — el operando es el valor literal 12 (sin corchetes), que va inmediatamente después de la instrucción.
¿Qué modo de direccionamiento usa MOV AX,[1100]?
Directo — los corchetes indican que el operando es el contenido de la posición de memoria 1100, no el número 1100.
📊 El profe: "les voy a tomar… la parte de direccionamiento para que me digan: si digo INC AX, implícito; MOV AX,12, inmediato; MOV AX,[1100], directo." Es el mismo contenido de M14.5, pero pedido al revés: en vez de escribir la instrucción, la clasificás.
🧠 trucoMirá el operando: sin operando → implícito · número suelto → inmediato · número entre corchetes → directo. Conecta con M14.5 y M8.15.
🚩 M14.7 · Flags que hay que saber
¿Qué flags del registro de estado hay que conocer?
✅ Respuesta de examenCinco: OF (Overflow, desbordamiento), CF (Carry, acarreo), SF (Sign, signo), ZF (Zero, resultado cero) e IF (Interrupt Flag). Una operación aritmética (ADD/INC) actualiza OF/CF/SF/ZF; el IF lo maneja el programador (STI/CLI) para habilitar o inhibir las interrupciones enmascarables.
📊 El profe: "sepan los que estudiamos: el overflow, el carry, el signo, el cero, y el flag de interrupciones, al menos sépanlo."
🧠 contextoEl registro de estado lo actualiza la ALU durante la ejecución (M8.11). El IF es la máscara de las interrupciones enmascarables (M12.3).
Siglas: OF / CF / SF / ZF / IF = Overflow / Carry / Sign / Zero / Interrupt Flag · STI / CLI = Set / Clear Interrupt Flag.
💡 ¿Con qué comandos veo la memoria como datos y como instrucciones?
D la muestra como datos (hex + ASCII); U la desensambla y la muestra como instrucciones. R = registros, E = editar memoria, A = ensamblar, P/G = ejecutar paso a paso / hasta el final.
💡 ¿Cómo escribo "sumar a CX el contenido de la dirección 200"?
ADD CX,[200]. Con corchetes = directo (contenido de la dirección). Sin corchetes (ADD CX,200) sería inmediato: sumaría el número 200.

Claves para el examen lo que más cae
💡 Tips de clase — claves para el examen
1. Escribir en castellano completo, no siglas sueltas. El profe penaliza "FI/DI/FO/EX" sin explicar.
2. Contador de Programa = dirección de la PRÓXIMA instrucción (no la instrucción, no el dato). La actual está en el IR.
3. Ciclo de instrucción ≠ ciclo de interrupción. Instrucción: búsqueda→decodificación→operandos→ejecución. Interrupción: Solicitud→Reconocimiento→Atención→Retorno. El error que más cae.
4. Ancho de banda = información POR UNIDAD DE TIEMPO. Sin eso, respuesta incompleta.
5. Paralelismo temporal (pipeline, 1/ciclo) ≠ espacial (varios pipelines, N/ciclo). No cruzarlos.
6. Los 3 problemas del pipeline (datos→forwarding/OoO · control→predictores · estructura→más unidades) con ejemplo + solución cada uno.
7. Memorizar completos: las 5 características del SMP y los 5 tipos dedicados (0–4).
8. Canales de E/S = 4ª modalidad (trampa de apuntes viejos). El canal-procesador tiene memoria propia.
9. DMA necesita 4 datos: origen, destino, longitud, modo. Se vuelve Máster del bus.
10. En la pila: CS:IP + flags (PUSH al entrar, POP/IRET al volver). STI como 1ª instrucción de la ISR = permitir anidamiento.
11. Ensamblador (práctica): comandos DEBUG R · D · U · E · A · P · G e instrucciones MOV · ADD · INC. D = datos, U = instrucciones.
12. Corchetes = direccionamiento directo (contenido de la dirección): ADD AX,[1100] ≠ ADD AX,1100. Sufijo del registro: AX = 16 bits, AL/AH = 8 bits.
